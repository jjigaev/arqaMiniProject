# Использование ИИ

Этот файл содержит фактический журнал, а не готовый рассказ о работе человека.

## Решения пользователя
- Выбраны FastAPI, PostgreSQL и Flutter Web.
- Подтверждена простая форма добавления поездки.
- Работа ведётся на main; коммиты требуют отдельного явного разрешения.
- Предложен AGENTS.md, чтобы правила работы с ИИ были видны в репозитории.

## Работа агента
- Подготовка плана, API, схем данных, миграций, Flutter-клиента, тестов и документации.
- Проверка идемпотентности, точности денежных расчётов и границ дня.
- Для графа кода в этой сессии нет доступных MCP-инструментов. Используются чтение исходников и точечный поиск.

## Ошибки и исправления
- Первоначальная проверка Python увидела Windows launcher, но запуск из песочницы не удался. Агент отдельно проверил реальный запуск вне песочницы: Python 3.11.9 доступен.
- Адрес JSON-манифеста Flutter вернул NoSuchKey. Агент перешёл к официальному Git-репозиторию Flutter вместо использования непроверенного зеркала.
- Первый тест узкого экрана обнаружил переполнение заголовка и навигации. Агент добавил адаптивные ограничения ширины; повторная проверка прошла.
- Dart LSP и pip freeze столкнулись с кириллицей в абсолютном пути. Для Flutter использован временный ASCII-путь через subst, для версий Python-зависимостей — pip list без Git-инспекции editable-пакета.
- Визуальная проверка формы обнаружила слабый контраст выбранного способа оплаты. Агент задал явные цвета выбранного сегмента в общем ThemeData. Семантическое дерево Flutter включено на время жизни экрана для доступности web-клиента без отдельного жеста активации.
- Пользователь заметил, что поля денег допускают текст, а общий интерфейс выглядит шаблонным. Агент исправил недостающую фильтрацию (числовая клавиатура сама не запрещает буквы), заменил строковый ввод дат календарём и отдельным временем. По запросу пользователя исследованы реальные продукты; источники и направление переработки записаны в DESIGN_REFERENCES.md. Позже пользователь выбрал B — «Лагуну»; перенос описан ниже.

## Дизайн-исследование, 7 октября

- Пользователь уточнил аудиторию: водители, ежедневное использование, и попросил более красочный интерфейс. Агент подготовил три интерактивных концепта и план переноса вместо немедленной замены рабочего Flutter-клиента.
- Использованы frontend-design и frontend-design-premium; MCP браузера — для визуальной проверки и сценариев взаимодействия. Отдельные HTML-макеты позволяют быстро сравнить композицию и цвет на одинаковых исходных данных.
- Первый мобильный макет слишком далеко отодвигал список. Агент уменьшил сводку, убрал дублирующий счётчик из её мобильного блока и увеличил подписи оплаты. В диапазоне ночной поездки сначала не было признака следующего дня; добавлена явная отметка.
- Проверки и границы макетов: [design-lab/VERIFICATION.md](design-lab/VERIFICATION.md). Пользователь выбрал B — «Лагуну» за понятность и удобство. Три концепта сохраняются как материалы исследования.

## Проверено агентом

38 backend-тестов на PostgreSQL при первоначальной проверке; после доработки формы — 11 Flutter-тестов. В браузере первоначально проверены сводки, добавление, календарь с клавиатуры, узкий экран и восстановление после сетевой ошибки. Подробности и ограничения: [VERIFICATION.md](VERIFICATION.md).

## Перенос B — «Лагуна» во Flutter, 7 октября

- Пользователь выбрал направление; агент перенёс мятную палитру, коралловый знак, сводку слева и журнал справа, компактные мобильные строки и закреплённое добавление. Форма и сообщения используют общую тему; DESIGN.md и 13 цветовых токенов обновлены вместе.
- В журнале видны сумма, комиссия и доход каждой поездки. Диапазон дня берёт самое позднее окончание, включая пересекающиеся поездки и переход через полночь.
- Дополнительный тест на 320 px обнаружил переполнение навигации. Агент сократил подпись календаря и предусмотрел вертикальное расположение даты/времени в очень узкой форме. Для больших сумм строки перестраиваются, сохраняя полные значения.
- 16 Flutter-тестов проходят, анализатор не нашёл замечаний. Серверная логика не менялась; 38 backend-тестов — результат предыдущего этапа.


- Визуальная проверка обнаружила, что цветные сегменты полосы оплаты имеют нулевую высоту внутри Row. Агент задал растяжение по высоте; исправление проверено в браузере. Мобильная сводка уплотнена после сравнения с выбранной демкой.
