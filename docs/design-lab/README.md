# Дизайн-лаборатория

Три самостоятельных интерактивных концепта для обсуждения UI/UX. Это временные HTML/CSS-макеты, а не замена Flutter Web. Данные скопированы из `data/trips.json`; добавления хранятся только в памяти страницы. Макеты не обращаются к API и не изменяют PostgreSQL.

Запуск из корня репозитория:

```sh
python -m http.server 3001 --bind 127.0.0.1 --directory docs/design-lab
```

Открыть `http://127.0.0.1:3001/`. Доступны три направления, просмотр ширины телефона, соседние дни и календарь, пустой день, форма добавления, числовой ввод, проверка времён и комиссии, подтверждение закрытия изменённой формы, локальное обновление сводки. Переключение направления сбрасывает временные добавления.

Канонические стили макетов — `preview.css`; общая механика — `preview.js`. Все три концепта используют одни данные и одну механику, поэтому их можно сравнивать по внешнему виду и композиции. Родительская страница `index.html` переключает iframe с реальной адаптивной шириной. Нет внешних JS/CSS/CDN-зависимостей.

В рабочем приложении владельцами поведения остаются `DiaryController`, `TripForm`, `DiaryApi` и Flutter-пикеры. При переносе выбранного дизайна меняются тема и представление; прототипная логика не должна заменять существующие валидацию, точные деньги, защиту от дублей и безопасный повтор.

## Ограничения прототипа

Нет запросов к серверу, загрузки, сетевых ошибок, сохранения между перезагрузками и серверной идемпотентности. Денежные расчёты выполняются в целых копейках; форматирование использует Intl. Нативные HTML-пикеры дат/времени зависят от языка и платформы браузера; в Flutter сохраняются русские календарь и 24-часовой пикер. На узких desktop-колонках комиссия переносится в подпись времени, а в мобильных строках имеет отдельную подпись. Окончательная Flutter-верстка должна сохранять доступность каждой суммы на всех ширинах.
